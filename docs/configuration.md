# Configuration

Two YAML files configure a simulation:

- **`config/world.yaml`** describes the scene. It is read by `sim_lidar` (or by
  `lidar_sim::loadWorldFile()` without ROS).
- **`config/params.yaml`** holds the parameters of every node. `example.launch` loads it on the
  parameter server.

## World file

```yaml
objects:
- type: cylinder                  # plane | sphere | cylinder | ellipsoid
  description: Column             # optional, shown in error messages
  center: [-10, 30, 0]            # origin of the local frame [m]
  angles: [0, 0, 0]               # roll, pitch, yaw [rad], optional
  radius: 0.4                     # sphere and cylinder [m]
  plane_constraints:              # optional
  - normal: [0, 0, 1]
    point: [0, 0, 0]
- type: ellipsoid
  center: [-30, 0, 5]
  size: [28, 4, 4]                # semi-axes [m]
```

| Field | Used by | Meaning |
| --- | --- | --- |
| `type` | all | Primitive type |
| `description` | all | Free text, optional |
| `center` | all | Origin of the primitive's local frame, in world coordinates [m] |
| `angles` | all | Roll, pitch, yaw of the local frame [rad], $R = R_z R_y R_x$; defaults to zero |
| `radius` | sphere, cylinder | Radius [m], must be positive |
| `size` | ellipsoid | Semi-axes along the local x, y, z axes [m], must be positive |
| `plane_constraints` | all | List of `{normal, point}` half-spaces in the local frame, optional |

The shapes are defined in [primitives.md](primitives.md) and the constraints in
[constraints.md](constraints.md). Other keys are ignored. A malformed object stops the loader
with a message naming it, for example:

```
objects[0] (Sphere without radius): missing 'radius'
```

### Generating the world: `scripts/create_world.py`

The example hangar is generated by a script, which is easier to maintain than 56 hand-written
objects: frames of beams are loops, and dimensions are named constants.

```bash
rosrun lidar_sim create_world.py                 # overwrites config/world.yaml in the source tree
rosrun lidar_sim create_world.py my_world.yaml   # writes another file
```

`WorldBuilder` collects objects and writes them in the format above:

| Method | Arguments |
| --- | --- |
| `add_plane` | `center`, `angles`, `plane_constraints=()`, `description=''` |
| `add_sphere` | `center`, `radius`, `plane_constraints=()`, `description=''` |
| `add_cylinder` | `center`, `angles`, `radius`, `plane_constraints=()`, `description=''` |
| `add_ellipsoid` | `center`, `size`, `angles=(0, 0, 0)`, `plane_constraints=()`, `description=''` |
| `save` | `path` |

`constraint(normal, point)` builds one plane constraint. A minimal world, from a script placed
next to `create_world.py`:

```python
from create_world import WorldBuilder, constraint

world = WorldBuilder()
world.add_plane(center=[0, 0, 0], angles=[0, 0, 0], description='Floor')
world.add_cylinder(center=[5, 0, 0], angles=[0, 0, 0], radius=0.3,
                   plane_constraints=[constraint([0, 0, -1], [0, 0, 3])],  # z < 3
                   description='Post')
world.save('my_world.yaml')
```

## Parameters

Every node reads its parameters from its private namespace, so the top-level keys of
`params.yaml` must match the node names. All parameters are required except
`investigate/num_samples`. A missing one stops the node with a message like:

```
Missing or invalid parameter '/sim_drone/update_rate'. Is config/params.yaml loaded?
```

Angles ending in `_deg` are in degrees. Orientations use roll, pitch, yaw
([Conventions](conventions.md)).

### `sim_lidar`

| Parameter | Type | Default | Meaning |
| --- | --- | --- | --- |
| `world_file` | string | set by the launch file | Path of the world file |
| `world_frame` | string | `world` | Parent frame of the published TF |
| `lidar_frame` | string | `lidar` | Frame of the point cloud |
| `scan_rate` | double | 10.0 | Revolutions per second [Hz] |
| `num_azimuth_steps` | int | 1800 | Firings per revolution |
| `num_rings` | int | 16 | Beams stacked in elevation |
| `min_elevation_deg` | double | −22.5 | Elevation of ring 0 |
| `max_elevation_deg` | double | 19.6875 | Elevation of the last ring |
| `min_range`, `max_range` | double | 1.0, 100.0 | Valid range interval [m], exclusive |
| `intensity` | double | 60.0 | Intensity of every return |
| `num_threads` | int | 8 | Ray casting threads |
| `initial_position` | double[3] | [0, 0, 2] | Sensor position before the first `lidar_odom_gt` message |
| `initial_rpy_deg` | double[3] | [0, 0, 0] | Sensor orientation before the first message |

See [LiDAR model](lidar_model.md) for the meaning of the beam parameters.

| `trajectory/radius` | double | 6.0 | [m] |
| `trajectory/angular_speed` | double | 0.4 | [rad/s] |
| `trajectory/first_axis`, `second_axis` | double[3] | [0, 1, 0], [0, 0, 1] | Orthogonal axes of the circle plane |

## Standalone viewer

`lidar_sim_viewer` is the same simulation without ROS or RViz. It is built by the plain CMake
flow in the [README](../README.md) (`-DLIDAR_SIM_WITH_ROS=OFF`) and also by `catkin build` when
Qt 5 or Qt 6 is installed.

```bash
lidar_sim_viewer
lidar_sim_viewer --world my_world.yaml --params my_params.yaml
```

| Control | What it does |
| --- | --- |
| World / Params | Paths of the two YAML files. Browse opens a file dialog |
| Reload | Read the path currently in the box |
| LiDAR | `sim_lidar` block: rate, resolution, elevation, range, threads, static pose |
| Motion | Static pose, Circle (`sim_motion`) or Drone (`sim_drone`) |
| Waypoints | Drone mission. Times must increase |
| Apply | Rebuild the scanner and the motion model from the form. The file is not written |
| Save | Write `params.yaml` (frame names and RViz marker styles are kept) and apply it |
| Play / Pause / Reset | Integrate the circle or the drone. Reset returns to `t = 0` |
| Speed | 0.5x to 20x. The drone mission is about 100 s at 1x |
| World, Points, Sensor, Path, Wire | Toggle the mesh, the cloud, the sensor axes, the trajectory and a wireframe |
| Left drag / right drag / wheel | Orbit, pan, zoom. `F` frames the scene |

Planes are drawn translucent. Planes and cylinders are infinite in the simulation; the viewer
draws a plane across the rest of the scene and a cylinder only where its axis crosses that
scene, then applies the plane constraints. The point cloud is the real ray cast, so a return
lies on the mathematical surface even where the drawn mesh is only an approximation.

`lidar_sim_viewer --check` loads both files, tessellates the world, computes one scan and exits.
It is a smoke test for a machine without a display.

## Launch file

`launch/example.launch` loads the parameters, starts `sim_lidar`, one motion node and RViz.

| Argument | Default | Meaning |
| --- | --- | --- |
| `world` | `$(find lidar_sim)/config/world.yaml` | World file given to `sim_lidar` |
| `params` | `$(find lidar_sim)/config/params.yaml` | Parameter file |
| `motion` | `sim_drone` | Motion node: `sim_drone` or `sim_motion` |
| `rviz` | `true` | Start RViz |

```bash
roslaunch lidar_sim example.launch                              # drone, example hangar, RViz
roslaunch lidar_sim example.launch motion:=sim_motion rviz:=false
roslaunch lidar_sim example.launch world:=/path/to/my_world.yaml params:=/path/to/my_params.yaml
```

To change a few values, copy `params.yaml`, edit the copy and pass it with `params:=`. The node
names are fixed by the launch file, so keep the top-level keys.

RViz is started with `DISABLE_ROS1_EOL_WARNINGS=1`, which hides the ROS Noetic end-of-life dialog.
The Docker image sets the same variable globally.

Nodes can also run without the launch file:

```bash
rosparam load $(rospack find lidar_sim)/config/params.yaml
rosrun lidar_sim sim_lidar _world_file:=$(rospack find lidar_sim)/config/world.yaml
rosrun lidar_sim sim_drone
```
